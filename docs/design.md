# 弈宝：设计与验证记录

更新：2026-10-13。对应当前向量检索版，按作业题六项交付要求组织。详细验收见 [项目梳理](project-audit.md)；历史实验不作为当前版本成绩。

## 1. 范围、运行与环境

单游戏《王者万象棋》、单原创向导“弈宝”，提供知识问答、情境建议、闲聊和能力边界说明。流程自行编排，依赖 FastAPI、Pydantic、httpx、FastEmbed 和 Qdrant，未接入 LangChain、Jev 或多 Agent 框架。没有账号、战绩和实时对局访问能力。

已验证 Windows / Python 3.11.5。安装 requirements-dev.txt，首次从 .env.example 创建 .env，填写后端 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL；已有配置不要覆盖。完整命令见 [README](../README.md)，精确依赖见 requirements-lock.txt。

依次运行 `python -m scripts.index_knowledge` 和 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`。首次索引联网下载嵌入模型，之后复用 data/models/ 与 data/vector/。原始知识随仓库提供，模型和数据库不提交。Qdrant 本地目录只允许一个进程占用，索引及独立评测前停止后端，服务保持单 worker。

用户已配置 API，历史真实调用成功；当前向量版的完整真实回答验收仍未完成。Mock 仅作联调并明确标注；健康接口的配置齐全标志不保证模型服务可达。

## 2. 接口与流程

POST /api/chat 接收 message/history，经过输入校验→上下文整理→规则意图识别→条件检查→按需模型检索规划→检索→模型生成→引用校验。返回 answer、intent、status、sources、retrieved_ids、retrieval_plan、latency_ms、timings_ms、mode、model_used 和 request_id。网页及离线评测共用 Agent.chat。

意图模块独立可测：正常live由大模型同时判断四类意图、必要澄清和检索计划；纯未接入能力请求说明限制，混合请求保留可回答游戏部分，检索未命中保持知识意图。旧规则只在Mock或模型分类失败时回退，响应明确记录。情境缺项由模型结合历史判断，不再强制匹配固定字段正则。详见 [本轮改造](agent-upgrade.md)。

历史最多12条、12000字，整理后保留最近6000字。live交给分类规划模型承接用户主题、数字、实体和指代，回退才使用旧上下文规则；历史助手文本不作为事实证据。页面支持连续对话、清空、等待、失败重发和原文来源展示，会话仅在内存保存。

意图与规划在一次模型调用中完成；需要检索时输出查询、关键词、实体、模式和历史开关，结构允许最多4条，提示优先1条、复杂最多3条，向量执行最多3条（含还原问题）。结构合法不能保证语义正确。闲聊直接回复，澄清和能力说明不再生成；知识生成只接收相关证据和有限历史。

后端验证 JSON、长度、引用属于本次证据，以及引用片段逐字出自对应正文；无依据时允许空引用并返回资料不足。网页展示原文、来源链接、层级和日期。当前没有逐句推论核验器，真实引文仍不等于支持所有结论。用户、历史、资料均按数据输入，客户端禁止 system 角色，网页使用 textContent；这些措施不能证明完全抵抗提示注入。

## 3. 知识库设计

官网基础知识30条，Wiki片段7701条，合计7731条。按规则、对象字段、卡面效果、解释及公告等可引用单元组织，包含 ID、主题、正文、来源标题/链接、日期、版本范围、实体、模式、事实类型和核验层级。覆盖目标与资源、英雄、棋手、装备、天赋、机制、成就、钻石狂潮、攻略、公开阵容和更新记录等。

wzwxq.com 是本项目接受的知识来源，但网站收录原文、站方解释、工具模型和待确认项仍区分，不能全部称为官方核验。原始快照、覆盖记录和85个工具模型分片随工程保存。924项站内搜索对象有映射；全覆盖指已枚举公开快照，不含无法获取的动态社区阵容、私有分享或站外数据。详见 [知识说明](full-wiki.md)。

默认512维 BGE 中文嵌入与 Qdrant 本地库。长正文按350字符窗口、300字符步长嵌入，平均归一化为记录向量，正文完整保存在 payload。向量查询最多召回100个候选，补充明确实体，再结合词法、标题、别名和语义分数排序，多查询合并后最多取6条。多英雄购买优先覆盖费用及各英雄原文。平均向量可能稀释长文局部事实，6条证据也限制复杂问题覆盖。

按模式、核验状态、待确认和历史范围过滤。未知、待确认或版本未核验时说明资料边界。来源层级和日期有助识别冲突，但尚无通用矛盾检测、跨版本裁决和任意版本查询能力。

更新流程：抓取→解析归档→构建记录→检查覆盖和来源→停止后端→重新索引→回归检索与回答；支持从快照离线重建。源文件、模型和处理版本组成索引指纹，不匹配时拒绝旧库。向量化不会缩小原始资料；模型及数据库增加磁盘占用。并发或规模增长可迁移 Qdrant 服务端，当前不宣称已验证内存优化。

## 4. 离线评测与真实结果

固定集32例36轮，含四类意图、两组三轮、资料不足、澄清、能力限制、混合请求和用户注入。标签及评分规则只传评测器。运行 `python -m eval.run --mode live --output eval/reports/实验名` 输出逐轮、汇总及待人工复核记录；最终验收前需先审计过时标签。

评分结合事实正则组、禁止断言、状态、引用，以及建议五维度：行动、条件、代价收益、调整条件、证据边界。建议至少8/10且关键维度通过。意图、回答、成功率分母为全部轮次；检索分母为预期知识非空轮次，Hit 为至少命中一项，Recall 为预期条目覆盖比例；成功、失败和评分耗时分开。规则通过率不是语义正确率，尚未采用模型评审。

| 历史真实模型 2026-10-13-live | 成功32/36，回答规则29/36，建议0/4；成功中位4.12秒、P95 7.10秒 | 旧检索与当时配置 |

现有评测缺口：WX04仍要求钻石狂潮资料不足；旧编号均存在，但同义新证据可能被编号交集评分误判。生成失败的阶段归因与调用计数已修正，旧报告保持原口径。向量模式的baseline/enhanced也不是原词法算法的纯对照。最新9例真实回归、耗时和引用结果见本轮改造报告，仍需修正全集标签并人工复核。

一次可复核改进：向量首次10例中9例命中，补充机制实体候选后达到10/10。用户反馈的详细追问、五英雄购买和输出截断问题也有回归测试。但没有提交者已完成逐条人工答案复核的记录。

## 5. 效率与取舍

知识回答通常一次分类规划加一次生成；闲聊、能力限制和缺条件追问通常一次分类调用。当前DeepSeek默认关闭额外思考，复用TLS配置和请求内连接。生成截断且预算不足4000时最多提高到4000重试一次，两次共用生成超时。默认分类规划20秒、生成45秒，不是含排队和检索的严格全请求65秒上限。

提供阶段耗时，嵌入在线程执行，复用索引并设置有界查询缓存。尚需重新测量当前完整真实链路的延迟分布，未做并发压测。未全程计时，实际投入工时未记录，不能编造。范围保持单游戏 Demo，不增加账号、云部署、会话数据库或多 Agent。

## 6. AI开发与人工核验

Codex参与需求、资料、代码、测试、排错和文档；运行时使用配置的Chat Completions服务及本地BGE，历史报告保存当时模型名称，密钥不进入交付物。

用户亲自测试发现“讲详细点”丢失上下文和购买建议失败；开发代理检查调用与代码，修正上下文、截断及证据覆盖。用户反馈与代理修正分别署明，不能将代理检查冒充提交者亲自审查。提交前仍需人工检查基础事实、建议条件与数值、多轮、未知和注入样本，记录依据和结论，并补充可核实的投入时间说明。
