## 核对出的关键问题

1. 旧设计文档写88条、无API、无向量库、40/53项测试，已经过时；本次替换为当前实现，并区分历史与现状。
2. 固定集所有预期知识ID仍存在，但新Wiki有等价内容，单纯ID交集可能误判。不能简单删除旧ID或放宽到任意引用，应建立经过检查的等价证据组。
3. WX04问钻石狂潮苏烈技能，仍预期资料不足；全量库现已支持此模式，应按来源重新标注。现有建议评分还含“费用未知”边界，需逐例检查是否被新资料改变。
4. eval/run.py在生成异常时把意图/检索也计错，无法区分前面阶段已成功。real_model_calls只统计成功生成标志，未计规划、失败与重试，不能用于费用估算。
5. 向量模式下baseline仍使用增强向量检索，而上下文增强可能不同，不能解释为旧词法基线对照。纯词法实验需显式设置RETRIEVAL_BACKEND=lexical；向量与词法比较应另立实验。
6. 目前“核查答案”是在线格式/引用校验与离线规则评分，没有自动逐句事实核验。建议通过引用检查，也可能错误理解技能条件、混淆购买与上阵或漏掉预算限制。
7. 本地Qdrant有进程独占约束，运行服务时再独立启动评测会冲突。索引必须先生成；首次下载依赖网络。这些都是评审复现说明必须包含的步骤。

## 验证与报告解释

数据核对：30条官网+7701条Wiki=7731；32例36轮；预期知识编号缺失数为0。

当前向量专项：eval/reports/2026-10-13-vector/query-final.json为10/10，live=false、planner_attempts=0，只证明实际中文嵌入检索的这10个样本命中。multi-hero.json证明购买成本与五个英雄资料均被取回。api-mock.json是接口联调，不是模型答案评分，而且早于最终多英雄证据修复。

历史真实报告：2026-10-13-live成功32/36、回答规则29/36、建议0/4；不能推广到当前向量版。预算4000的历史报告成功34/36、回答规则仍29/36、建议仍0/4，且失败耗时明显偏长；不能只挑成功或高分结果展示。

自动测试：本轮正常本机环境执行 `python -m pytest -q`，82项通过，耗时45.31秒；1条Starlette/httpx弃用提示。沙箱尝试停在TestClient阶段后已终止，最终成绩来自本机完整运行。单元测试包含模拟模型和固定测试向量，不能代表模型语义正确率。

## 建议收尾顺序

1. 审计固定集标签：模式支持范围、版本、等价证据和建议条件；补入用户反馈的两个完整回答回归案例。
2. 修正评测阶段归因及调用计数，记录检索后端、嵌入版本、源数据指纹和超时/预算。
3. 在当前向量版本跑真实全量评测，保留失败、逐轮回答及延迟；对基础事实、建议、多轮、未知、注入做人工证据核对。
4. 针对实际错误完成一次前后对照，再做最终浏览器走查；整理当前报告入口，补充真实人工审查与工时说明。

不建议此时为作业再引入新Agent框架或额外基础设施；先把可运行、可复现、可验证的现有链路交付完整。
