# 模型路由、引用原文与响应优化

2026-10-13。对应本轮五项修改，原始实测保存在 `eval/reports/2026-10-13-agent-upgrade/`。重启后端即可生效，数据库和嵌入模型不变，无需重建索引。

## 当前链路

用户问题和最近历史 → 大模型一次完成四类意图、上下文还原、澄清判断与检索规划 → 需要时查询本地Qdrant → 模型组织亲切简洁的回答和引用片段 → 后端逐字验证引用 → 网页展示回答、原文、链接、分层和日期。

正常live请求由模型分类，旧规则仅用于Mock和分类失败时的明确回退，响应routing记录实际状态，网页也会提示回退。闲聊直接使用分类调用的短回复；能力请求使用本地边界说明；澄清无需再次生成。知识与建议通常只需两次模型调用，没有新增一个串行“意图模型”步骤。

## 引用能保证什么

生成模型必须提交实际使用的source_ids及对应quotes，后端检查每个片段是相应资料body的连续原文，拒绝未知编号、缺片段、改写片段及无依据链接。片段使用textContent展示，不执行资料中的HTML。无相关证据可返回insufficient_evidence及空来源，不能为了通过校验随意挂引用。待确认资料单独说明，其引用不代表已经确认。

这保证展示的片段来自已收录资料，不等于逐句证明答案推论正确。回归中发现“购买”与“登场”仍可能混淆，因此建议类在六条主体证据之外，可补最多两条原文中出现的触发时点定义。事实和建议仍需语义评测；没有宣传为零幻觉。

## 慢在哪里，如何处理

改造前对“万象大赛有几个人，怎么赢？”实测28.53秒：上下文约0.01秒、检索规划14.16秒、检索7.20秒、生成7.15秒。该次未记录各模型调用的推理token，不能将全部等待精确归因给思考模式。

实际修改：

- 合并意图与检索规划，不再预检索一次或发送全实体目录；该问题规划输入从4685字符目录负载缩为少量元数据。
- 向量检索只对原问题及改写最多执行三次，不再额外嵌入关键词拼接串。实体通过清单ID直接读payload，减少全库scroll；五英雄购买的费用和各英雄原文可直接定位。
- 在当前DeepSeek模型上关闭额外思考，并启用JSON模式。`LLM_THINKING=auto`只对名称含DeepSeek的模型发送关闭参数；其他服务不自动发送。可设置enabled/disabled，服务支持情况须联调。
- 一个请求内复用HTTP连接，跨请求复用TLS信任配置，保持证书校验；记录客户端初始化耗时，避免遗漏本机准备开销。
- 生成只传需要的证据字段；简单问题简答，用户要求详细才展开。固定快照说明移到来源区，不再追加到每段正文。

参数依据：[DeepSeek思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions JSON格式](https://api-docs.deepseek.com/api/create-chat-completion/)。本机使用的是代理服务，最终是否兼容以实际返回为准；本轮返回的reasoning_tokens为0。

## 实测及范围

第二轮相同9个场景（after.json）：请求成功9/9、预期意图9/9；6个带来源回答的片段全部逐字匹配；中位耗时5.93秒。包括基础规则、详细追问、多英雄购买、口语预算、情绪闲聊、缺条件、未接入能力、钻石狂潮和用户注入。全部走真实模型和实际向量库，不向Agent传评测标签。

最终检索十类栏目10/10，见retrieval-final.json。自动测试94项通过（72.30秒，1条已有Starlette/httpx弃用提示），包含模型分类、回退、逐字引文拒绝、无证据回答、并发调用日志隔离、费用/多英雄覆盖和时点定义；前端JS语法检查通过。

补充时点资料后的最终HTTP专项保存在api-final.json：购买问题200/answered，6.62秒，明确说明孙尚香和武则天的登场前提；虚构英雄问题200/insufficient_evidence，5.08秒且sources为空。购买建议仍未据此证明是最优方案，阵营关系等未取到的证据会限制建议。

本轮浏览器实际验证了等待状态、格式错误提示、重新发送，以及展开后显示原文、来源链接、来源层级和日期。一次购买回复被格式/引用校验拦下，界面显示502对应的友好错误；随后明确“最多6条、不重复、编号与片段一一对应”的输出约束，重试成功约7.1秒。首次异常未保存模型原始返回，不能断言唯一根因或保证以后不再发生；校验失败仍会拒绝展示答案。

## 可观测性和剩余边界

响应提供routing、model_calls及client_setup/intent_planning/retrieval/generation耗时。model_calls逐次记录请求耗时、token预算、服务实际返回的token计数及完成原因，不记录密钥、原始服务错误或思考内容。离线评测生成失败时保留已完成的分类与检索结果；调用计数包含分类、生成、失败与重试，旧报告不改写。

旧32例固定集仍存在模式边界和等价证据编号问题，尚未将其过时标签包装成当前真实全集成绩。模型路由和原文引用均有失败可能，回退或错误会明确呈现。人工逐句事实及建议优劣验收仍是独立工作。
