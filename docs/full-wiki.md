当前生成7701条Wiki检索片段，运行时合计7731条（不是7731个独立对象）。网站公开搜索索引924个对象全部映射，未覆盖项为0。覆盖清单包含栏目、对象、片段ID、路由和文件哈希，可见`data/wiki/coverage.json`。

“全量”边界是本次可访问的公开页面内容和公开数据，不包括私人棋盘、未知分享码、账号资料或站外数据榜单。`/api/lineup-presets`本次返回SPA HTML，未提供公开动态列表；已采用站点自带完整精选快照，不能宣称穷尽其他用户发布的动态阵容。图片链接保留，未将截图中的未知文字伪造为知识；工具代码没有被移植为游戏模拟器。

## 来源与版本

- `wiki_original`：Wiki收录的原文，不能冒称全部已独立官网核对。
- `wiki_reference`：Wiki结构化字段；原始属性与显示单位保留区分。
- `site_interpretation`：Wiki解释，可用于事实问答或建议，但需保持归属。
- `site_model`：工具固定条件模型数据，不能作为实战胜率/强度保证。
- `pending`：站点明确标注待确认，普通检索排除；特定待确认问题直接说明边界。
- `official_original`：保留仍能严格匹配旧独立核验文本的字段及官网链接。

历史和下架资料完整归档，默认不作为当前知识检索；显式历史/更新问题可检索。公告只保留各自日期，不自动把多个版本混成“当前规则”。不同模式分开过滤；“通用”表示站点说明或跨玩法公告，不代表跨玩法卡牌数值通用。模型仍可能误读版本，尚无完整的版本生效区间推导。

## 当前检索流程

1. 正常live由模型一次完成四类意图、上下文还原、澄清判断和检索规划。输入为用户问题、近期历史、固定栏目以及最多32个文本中出现的实体名称，不先检索向量库或发送完整目录。参考答案与评测标签不进入请求。
2. 知识和建议请求返回结构化`queries/keywords/entities/mode/include_history`；闲聊直接使用该次模型短回复，缺必要条件时澄清，未接入能力使用本地边界说明。模型分类超时或输出非法时用旧规则回退，并明确记录`fallback`；缺少模型配置直接报错。
3. 需要检索时先检查已知待确认项；命中则说明边界。其余将模型还原的问题与规划查询去重，实际最多执行3条查询。向量查询结合模式/状态过滤、明确实体补充和词法排序，合并最多6条主体证据；建议类可另补最多2条触发机制定义。多英雄购买优先覆盖费用及各英雄原文，覆盖充分时可直接读取这些记录。
4. `keywords`保留用于前端展示及词法后端，向量后端不单独嵌入关键词串。模型还原的问题中明确指定模式时可覆盖规划模式，但还原本身仍可能出错，当前没有保证用户原始文本始终独立参与检索的硬约束。
5. 如问题明确要求某英雄某等级的装备价值，从本地完整分片读取站点结果并附带条件，作为`site_model`证据，而非重新计算实战效果。没有足够证据时说明资料不足。
6. 有证据时再调用模型生成回答，最终最多展示6条来源。后端核对ID与片段；引用不匹配时保留正文，改为展示对应记录的真实摘录并标注供参考，未知来源省略。没有可用正文才自动重试，仍失败则展示已有资料。网页展示片段、链接、层级和日期；响应保留`retrieval_plan`、`routing`、`model_calls`及`intent_planning/retrieval/generation`等阶段耗时。这不等于逐句验证回答推论正确。

Mock模式仍使用规则生成查询，明确标记`mock_rules`。正常live的知识和建议通常共两次模型调用，闲聊、澄清、能力说明及无资料请求通常一次。生成截断可能追加一次重试。分类规划预算默认2000 token、20秒，可通过`LLM_PLANNER_MAX_TOKENS/LLM_PLANNER_TIMEOUT_SECONDS`设置；生成默认700 token、45秒，截断重试与首次生成共用生成超时。

查询生成不能保证永远正确。格式校验、提示约束和回退不能证明改写的语义准确，也不能把10个检索案例全过当作回答质量验收。

## 重建和更新

离线重建（不需要Node、不联网、不依赖artifacts缓存）：

```powershell
.\.venv\Scripts\python.exe scripts/build_wiki.py --from-snapshot
```

完整刷新（只读公开HTTP，静态解析JS，不执行下载的站点脚本）：

```powershell
npm install --prefix artifacts/wiki-tools --no-audit --no-fund acorn@8.15.0
.\.venv\Scripts\python.exe scripts/sync_wiki.py --tools
.\.venv\Scripts\python.exe scripts/build_wiki.py
.\.venv\Scripts\python.exe -m pytest -q
```

`--reuse-cache`仅供恢复中断采集，不等价于重新联网刷新。网站目录和内嵌数据结构变化可能要求更新解析器；刷新后必须检查覆盖清单和差异，不能只看命令退出码。原始站点模块在忽略的artifacts目录，结构化内容全快照在`data/wiki/snapshot.json.gz`。装备分片独立压缩保存并校验哈希。

上述离线重建或联网刷新改变知识记录后，需要停止占用本地Qdrant的后端，运行 `.\.venv\Scripts\python.exe -m scripts.index_knowledge` 重建向量索引，再执行检索/回答回归并启动后端。仅重启不会自动重建索引，源文件指纹不匹配时拒绝使用旧库。
