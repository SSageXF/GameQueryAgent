# 万象大赛资料导入（2026-10-13）

本轮新增27个对象、58条分层记录。与原有30条官网新手知识合并后共88条：75条规则/官方原文或入门推荐、9条站方解释、4条待确认。并非88条全部都是已确认规则。

## 来源、筛选和核验

读取知识站的公开 `explorer-catalogs/{hero,equipment,effect,talent}.json`。入口来自该站实际前端引用，[图鉴索引](https://wzwxq.com/atlas)将这四类列在“排位·万象大赛”下；不采集钻石狂潮目录。

四份目录共551个候选对象，排除37个历史/补充/下架对象，487个对象暂不纳入本次新手范围，选择27个。选择清单固定在 `scripts/import_wzwxq.py`，覆盖成长英雄、基础装备、资源效果牌和不同取舍的天赋。名称和官方raw_id必须一致，不能只根据同名合并。

从[官网卡牌加载脚本](https://wxq.qq.com/cp/a20260707sfgw/js/cards.js)找到腾讯公开数据文件 `https://game.gtimg.cn/images/amside/ide_timer/589094_oscard_new_{1,4,2,8}.js`。对选中对象的卡面、觉醒和技能说明去除HTML样式标签及空白后逐字段完全比对，45项全部一致。没有把站方写的“官方”标签直接作为核验结果。

比对范围只包括这些文本字段，不包含完整属性成长、40/100级强化、模拟伤害、概率、触发顺序或版本公告全量一致性。站点的“官方2026-09-29”作为站方版本标签保存；官网文件为本次采集快照，不据此声称对应某个正式版本或永久最新。

## 三层证据如何使用

| 层级 | 本轮数量 | 使用规则 |
| --- | --- | --- |
| `official_original` | 45 | 同ID同名、文本与官网一致后启用；默认事实检索可使用 |
| `site_interpretation` | 9 | 保留站方归属，非官方结论；仅情境建议检索允许，且同时保留其官方父资料 |
| `pending` | 4 | 默认事实检索排除；命中特定待确认问题时直接说明不确定，引用用于解释资料边界，不送模型生成确定结论 |

待确认项：苏烈复生是否重复触发牺牲、曜额外等级叠加顺序、孙膑不同英雄施法计数是否独立、盾山古币自动使用时点。这些记录不是事实断言。未来官网字段与站方文本不一致时，也归入隔离的pending并保留两边文本，不能自动覆盖。

示例：问“苏烈觉醒卡面是什么”可检索已比对原文；问“苏烈复生后是否重复触发牺牲”返回待确认。问“钻石狂潮里苏烈技能”明确告知当前资料范围，不能借用万象大赛规则。

引用区显示证据层级、采集及版本范围，并提供站点详情与官网比对数据链接。原有只显示“官网新手快照”的统一尾注已改为按引用查看实际来源。

## 复现与更新

```powershell
# 不联网：依据仓库内选中字段快照，重新生成导入结果和审计
.\.venv\Scripts\python.exe scripts/import_wzwxq.py
# 联网更新：获取四份站点目录和四份官网数据，重新筛选、比较
.\.venv\Scripts\python.exe scripts/import_wzwxq.py --refresh
```

- `data/imports/wzwxq-selected.json`：仅选中字段和来源、时间、模式依据；完整临时下载在被忽略的artifacts目录。
- `data/imports/wzwxq-audit.json`：候选数量、排除原因、两边文件指纹、45项比对结果。
- `data/wzwxq.json`：实际接入检索的分层数据。

更新后审阅JSON差异、冲突/排除数量，再跑测试与评测；脚本不会将不一致字段放行。逐字段一致只证明两个快照在该字段相同，仍需要人检查语义、版本和客户端表现。本次核验由开发代理执行，不能冒充项目提交者的独立人工核验。公开前端目录不保证稳定；本地副本避免运行时依赖站点。
