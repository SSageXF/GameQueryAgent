# 情境建议评分 v2

> 2026-10-14：主评测已更新为37例49轮，见[评测说明](README.md)。本文五维规则继续使用，升级实际费用仍需按按钮核对；模式和等价引用标签已修正。末尾Mock成绩属于历史实验，不能代表当前真实模型质量。

旧版检查关键词和来源，复述问题、罗列资料也可能通过。v2对“需要实际建议”的案例增加五个维度，每项2分，总分10；至少8分且所有关键维度通过，才通过自动规则检查。需要澄清的案例仍按缺项追问和禁止直接决策评分，不强制输出完整建议。

| 维度 | 要求 | 是否关键 |
| --- | --- | --- |
| 行动 | 明确下一步，例如暂缓升级、在预算允许时升级；“先看规则”不算 | 是 |
| 条件分析 | 将玩家资源、新手身份等条件与决策原因联系起来 | 是 |
| 代价与收益 | 比较升级/阵容选择的收益与买牌、补强等机会成本 | 否 |
| 调整条件 | 说明什么情况下应换方案，不能只有永远正确的空话 | 是 |
| 证据边界 | 不编造未知费用和强度；指出按钮、原文或待补信息 | 否 |

具体正则和禁止建议保存在每个案例的 `advice_rubric` 字段，只传给评测器，不能传入Agent。过滤“你给出的条件是…”等复述行、引用行和完整问题的照抄；逐维度保留匹配证据。加入2能量/低生命与30能量/高生命两个资源对照案例，但费用未知时允许条件式结论，不强制模型凭空给一个唯一动作。

正则依然可能误收无因果关系的文字、否定或错误建议，因此命名为“情境建议规则通过率”，不是语义正确率。数字一致不代表计算正确，链接存在不代表支持建议。报告默认 `quality_evaluation_complete=false`，不因自动分高而解除。

每次运行另外输出 `*-manual-review.json`，包含问题、实际回答、维度和待填写检查表；reviewer为空、verdict=not_reviewed。人工需逐项确认：条件是否真实参与决策；事实/数值是否有据；站方解释是否归因；方案是否可执行；是否虚构待确认机制。关键事实错误、能力越界、虚构数值或把未确认机制当事实，人工判不通过，即使自动分达到8分。
