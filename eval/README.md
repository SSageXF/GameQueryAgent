# 固定数据集离线评测

离线指基于固定样本批量运行，不依赖在线玩家流量；live仍调用配置的模型API。Mock只检查程序链路，不能作为回答质量成绩。

## 交流方式专项

`voice-cases.jsonl`单独保留4例6轮：用户报告的升级澄清→介绍小乔→纠正为王者荣耀三问、一句话效果、已有等级/能量的追问、查询战绩。主评测36例45轮的统计口径不变。

```powershell
.\.venv\Scripts\python.exe -m eval.run --mode live --dataset eval/voice-cases.jsonl --output eval/reports/voice-run
```

同样通过`Agent.chat`运行，不把`style_checks`、答案要点或预期来源传给Agent。报告新增两份实际system prompt的SHA-256，人工检查模板带入每轮`style_checks`。事实规则通过不代表语气合格；“呀”“哦”“咱们”等词出现也不能单独证明亲和。逐轮检查：

| 维度 | 检查内容 |
| --- | --- |
| 承接对话 | 是否回应当前请求，用户纠正时是否承接；是否重复索取已知信息 |
| 交流负担 | 澄清是否只追问一两项真正缺少的条件；是否像填表或把责任推给用户 |
| 讲解方式 | 介绍是否让玩家理解作用，而非只贴原文；用户要一句话时是否保持简短 |
| 范围说明 | 是否解释相关限制并给贴切下一步；是否机械宣读服务范围、硬拉回被否定的话题 |
| 事实边界 | 触发、数字、范围是否准确；自然解释是否额外编造时机、强度或“不受某限制”等结论 |

每项由审查者标为通过、部分、未通过或不适用，并写对应原句依据；不与事实规则分数混成“正确率”。开发代理检查必须标明身份，不代替用户对语气的最终验收。

2026-10-14的修改前及迭代输出完整保存在`reports/2026-10-14-voice/`。`before`使用旧提示词，三轮事实规则均通过，但实际仍有问卷式追问、纠正后硬拉回原话题，说明旧指标未覆盖体验问题。`after`、`final`、`final-v2`是不同提示词的中间实验，目录名不代表最终验收；`checked`是当前提示词的针对性复测。已有条件的VOICE03在部分实验中先检索再作条件式回答，严格预期澄清因此失分，需要结合原文复核，不能直接当作语气失败或宣称已解决所有建议质量问题。

本机网页后端占用Qdrant时，本次使用同一索引的SQLite一致性备份运行真实Agent，原网页服务未重启；没有用Mock替代向量检索。普通复现仍按下文先释放本地索引。实际回答、引用、输入历史、提示词指纹和逐轮耗时都保留；小样本不能证明每次都自然。

当前提示词`checked`复测5轮均返回内容，其中4轮正常模型路由、1轮分类回退后仍生成了可读介绍。事实规则5/5不能当作亲和5/5：升级追问仍出现3项，介绍仍偏资料讲解；纠正后的承接、范围说明及简答要求表现改善。[开发代理逐条检查](reports/2026-10-14-voice/developer-review.json)保留这些局限，不以中间某次较好输出替代最终结果。

## 运行与报告

先配置`.env`并建立向量索引；本地Qdrant同一目录只能被一个进程打开，独立评测前停止网页后端。

```powershell
.\.venv\Scripts\python.exe -m eval.run --mode live --output eval/reports/my-run
# 只复测固定集中的能力边界与切回本游戏场景
.\.venv\Scripts\python.exe -m eval.run --mode live --cases MT04,MT05 --output eval/reports/scope-run
```

输出`live-enhanced-all.json`（逐轮回答、真实历史、来源、判断依据和汇总）、同名Markdown汇总，以及`*-manual-review.json`人工检查模板。指定案例时文件名附`-selected`，报告也保存实际选中ID，不能把专项成绩当全集成绩。使用不同输出目录保存不同实验，避免覆盖历史。

固定集在[cases.jsonl](cases.jsonl)。启动时校验编号唯一、必备标注、正则合法及所有预期知识ID存在。模型预算、超时、思考开关、模型名称、向量集合、数据集/知识/评分代码指纹均保存在报告中；不记录API密钥。相同输入可以重复执行，但在线模型和网络可能产生不同答案和耗时，不承诺逐字复现。

## 第5项要求核对

| 要求 | 当前实现 |
| --- | --- |
| 至少12例、四类意图 | 36例45轮；知识29轮、建议6轮、闲聊3轮、范围外7轮 |
| 至少2个多轮案例 | 5组，包含棋手、竞拍、天赋连续追问、连续不支持请求和切回本游戏 |
| 未覆盖、澄清、未接入能力、用户干扰 | U01/V01、A01/A04/H03、O01及MT04、P01等 |
| 编号、输入、行为、正确要点和禁止项 | 每例turn都有`expected_intent/expected_behavior/answer_points/required_groups/forbidden_patterns` |
| 预期知识编号 | `expected_knowledge_ids`；经核对的等价来源归入`expected_knowledge_groups` |
| 网页相同Agent、无答案泄漏 | 都调用`Agent.chat`，边界只传`ChatRequest(message, history)`；多轮使用实际前轮回答 |
| 逐条和汇总、四类指标 | JSON及Markdown；见下表的定义和分母 |
| 实际结果、局限、人工检查 | 保存真实模型输出及规则失分原因；所有轮次生成待审模板，开发代理抽查单独标识 |

原32例36轮已更新：修正钻石狂潮苏烈的过时“不支持”标签；登记白歌、竞拍、天赋刷新及等级等价来源；未知问题不再必须照说“不能编造”；把近期用户回归加入同一主评测入口。没有移除旧失败案例来提高分数。原历史报告保留原口径。

## 指标与适用范围

| 指标 | 分母与通过条件 |
| --- | --- |
| 意图准确率 | 全部执行轮次，实际意图与预期一致；异常仍计入分母 |
| 检索命中率 | 预期知识组非空的轮次；至少命中一个相关知识组 |
| 平均证据召回率 | 各有证据轮次覆盖的事实组比例均值；组内ID为等价证据，组间是不同事实 |
| 回答规则通过率 | 全部轮次；关键事实、禁止断言、状态、引用、原文与来源完整性、行为约束及适用的建议评分都通过 |
| 整例通过率 | 全部案例；一例所有轮次均通过回答检查 |
| 成功率 | 全部轮次；正常完成，无模型错误或路由回退；资料摘录降级不算正常成功 |
| 响应率 | 全部轮次；返回结构化结果，包含降级回复，与成功率分别报告 |
| 耗时 | 全部/成功/失败各自的中位数、P95及数量；各阶段另记；评分耗时单列，不算进Agent耗时 |

规则不做完整字符串相等判断。需要资料的回答除预期证据命中外，还核对所有展示来源ID、URL和摘录是否来自实际知识记录；纯闲聊、澄清和范围外场景要求不检索、不挂来源。事实检查不因为“HTTP成功”“正文非空”或“检索命中”就通过。

当前没有引入第二个模型作裁判。规则能发现已定义的事实缺失、数字错误、能力越界及引用问题，但不能可靠判断任意语义、推理或策略优劣；自然表达可能误判，未定义的错误也可能漏判。`answer_pass_rate`是规则通过率，不是事实正确率。`quality_evaluation_complete`保持false，人工模板不会自动标成已审查。

情境建议按[五维评分](advice-rubric.md)检查行动、条件、机会成本、调整条件和证据边界；仍需逐句检查建议是否真的成立。对照原文的抽查结论与自动分数并列保留，不用人工标记覆盖原始自动结果。

## 2026-10-14真实全集结果
